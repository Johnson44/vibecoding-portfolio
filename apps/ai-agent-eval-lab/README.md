# AI Agent Eval Lab

一个独立运行的 AI Agent 评测工作台原型，围绕真实用户任务比较不同版本 Agent，并输出可追踪的质量与产品指标。

> 本项目是基于实习经历与公开场景设计的个人原型，不是凤凰网内部系统，也不使用凤凰网内部资料、用户数据或豆包内部接口数据。

## 在线体验与本地运行

当前版本提供 [公网 Demo](https://zsjohnson.site/ai-agent-eval-lab/)，默认使用脱敏数据和确定性演示结果。

```bash
# 在仓库根目录执行
pnpm install
pnpm dev:eval
```

打开 `http://localhost:5175/`，依次体验：

1. 选择一个真实用户任务
2. 点击“开始版本对比”
3. 查看豆包免费版与豆包收费版的五维评分
4. 查看问题证据、严重度、影响范围、修复优先级和评测报告

配置 CloudBase 环境后，评测请求可以优先调用统一 `aigc-api`；云端请求失败时会自动回退到本地演示模式。

## 任务测试集

| 任务 | 用户问题 | 主要观察点 |
| --- | --- | --- |
| 台风信息总结 | “请总结台风‘巴威’的预警信息，并说明哪些结论还需要核验。” | 时间与地区、官方来源、不确定性边界 |
| 旅行规划 | “请制定青岛周末两日旅行计划，预算 1500 元，遇到下雨要有备选方案。” | 行程可执行性、预算拆分、雨天备选 |
| 内容改写 | “把一段手机测评改写成适合小红书发布的内容，保留参数事实并加入行动引导。” | 平台语气、事实保留、转化 CTA |
| 图像提示词 | “生成一张烟雨江南女子撑伞图的指令，用于图像模型。” | 场景元素、主体动作、水乡建筑、构图与光影 |

任务不是抽象的“综合能力测试”，而是可被内容运营、编辑或普通用户直接提出的具体工作请求。每个任务都配置了可观察的期望信号，方便评测者判断“完成了什么”和“遗漏了什么”。

## 评测闭环

### 五维评分

- **任务完成度**：是否完成用户交代的目标，并覆盖关键要求。
- **准确性**：事实、数字、来源和关键约束是否可靠。
- **稳定性**：回答是否结构完整，是否出现明显缺项或不一致。
- **交互体验**：是否易读、可执行、符合用户场景，是否需要用户反复追问。
- **付费价值**：收费版相对于免费版是否提供了可感知、可解释的增量价值。

每个维度按 0–100 分计算，并汇总为任务总分。界面同时展示分差、获胜版本和优先修复项，避免只看一个总分做产品判断。

### 问题归因

系统将结果问题归纳为：

- 事实错误
- 幻觉或无证据推断
- 答非所问
- 格式错误
- 工具失败

每条问题包含证据、严重度、影响范围和修复优先级。高风险结论会提示人工复核，评测报告保留“问题—证据—建议”的链路。

### 版本对比

当前演示候选固定为：

- **豆包免费版**：代表基础能力和免费体验边界。
- **豆包收费版**：代表更高阶能力与付费价值假设。

两版使用同一任务和同一评分标准，结果差距来自任务完成质量，而不是把“收费版”直接写成高分，便于分析能力差异、修复优先级和后续实验方向。

## 产品设计取舍

- **本地优先**：不依赖实时模型、网络或内部接口，保证结果可复现。
- **可解释**：评分旁边展示证据和扣分原因，方便从“模型好不好”转向“产品问题是什么”。
- **人工兜底**：高风险内容不直接给出确定结论，而是进入人工复核流程。
- **分层展示**：先看任务与版本结论，再下钻到维度分数、问题标签和修复建议，便于快速定位问题。
